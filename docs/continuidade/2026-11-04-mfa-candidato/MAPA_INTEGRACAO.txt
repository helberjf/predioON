DECISION AND FIRST SLICE

Obligation = active account AND (legacy administrative flag OR021 current global
PLATFORM_ADMIN authority). This intentionally includes flag=true when role catalog
is inactive, because010 support authorization still accepts that flag. No change
to capability semantics: MFA never grants a capability. PLATFORM_SUPPORT alone
does not trigger the obligation. verified_at055 is never read as MFA evidence.

Candidate SQL contains persistence, three narrowly scoped helpers, three additive
RESTRICTIVE policies and one read envelope. The first protected objects are:
 public.organizations — preserve039 organizations_capability_read/insert/update;
 public.support_hosts — preserve010 support_hosts_admin;
 public.support_requests — preserve010 support_requests_admin.
New policies are *_session_mfa, FOR ALL TO predioon_app, USING + WITH CHECK.
They are ANDed with existing permissive policies; no permissions are broadened.
SELECT/DELETE old rows use USING; INSERT new rows use WITH CHECK; UPDATE both.
Without permissible rows, policies need not execute: use explicit envelopes below
for the operation-level403 contract, including empty lists/no-match updates.

WHY THIS CLOSES THE DATA-ACCESS GAP IN THIS SLICE

1. authenticate resolves the session and obligation using identity pool.
2. inTenantContext sets user_id, role AND session_id transaction-local.
3. An early app guard gives prompt403 but is not the race defense.
4. Every candidate protected table operation evaluates the new STABLE predicate
   in the SAME statement snapshot as its RLS capability predicate and row access.
   A binding committed after the assert but before SELECT is visible to BOTH
   decisions. The restrictive predicate raises PMF01/PMF02, aborting the query.
5. A later revocation cannot turn an already aborted statement into permitted data.
   No row result is sent before the transaction completes successfully.
6. For list organizations, app_list_mfa_organizations() is STABLE SECURITY INVOKER:
   PERFORM MFA then capability then RETURN QUERY share the calling snapshot;
   caller RLS remains enabled. This explicitly rejects even if the table is empty.

The assurance is at the operation snapshot. Changes committed after that snapshot
are observed next time, not globally linearizable. Lock-wait fresh-time semantics
of021 must remain: do not replace the entire runtime with REPEATABLE READ.
